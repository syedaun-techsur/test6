<task type="auto">
  <name>Task 1: Create index.html app shell</name>
  <files>index.html</files>
  <action>
Create `index.html` at the project root. This is a vanilla HTML/CSS/JS app — no build tooling needed.

Structure:
```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>To-Do</title>
  <link rel="stylesheet" href="styles.css">
</head>
<body>
  <div class="container">
    <h1>My Tasks</h1>

    <!-- Input area (non-functional in Phase 1 — wired in Phase 2) -->
    <div class="input-area">
      <input type="text" id="new-task-input" placeholder="Add a new task…" disabled>
      <button id="add-task-btn" disabled>Add</button>
    </div>

    <!-- Task list -->
    <ul id="task-list" aria-label="Task list">
      <!-- Task items rendered here by renderer.js -->
    </ul>

    <!-- Empty state — shown when no tasks exist -->
    <p id="empty-state" class="empty-state" hidden>
      No tasks yet — add one above!
    </p>
  </div>

  <script type="module" src="app.js"></script>
</body>
</html>
```

Key requirements:
- `id="task-list"` on the `<ul>` — renderer.js appends `<li>` elements here
- `id="empty-state"` on the `<p>` — renderer.js toggles `hidden` attribute
- `id="new-task-input"` and `id="add-task-btn"` — disabled in Phase 1, wired in Phase 2
- `<script type="module" src="app.js">` at bottom of body — loads JS entry point
- `<link rel="stylesheet" href="styles.css">` in head
  </action>
  <verify>Open index.html in a browser (or use `python3 -m http.server 8080` and visit http://localhost:8080). The page title shows "To-Do", the heading "My Tasks" is visible, and no JS errors appear in the console.</verify>

<task type="auto">
  <name>Task 2: Create styles.css with complete visual styling</name>
  <files>styles.css</files>
  <action>
Create `styles.css` at the project root with complete styling for all app states.

Required styles to include:

**Layout:**
- `body`: sans-serif font, light background (#f5f5f5 or similar), margin 0
- `.container`: max-width ~480px, centered (margin: 0 auto), padding, white background, subtle box-shadow, border-radius
- `h1`: reasonable heading size, margin bottom

**Input area (`.input-area`):**
- Flexbox row layout: input grows, button fixed-width
- Input: border, border-radius, padding, font-size matching body
- Button: background color (#4a90e2 or similar), white text, border none, border-radius, cursor pointer, padding matching input height
- Button disabled state: reduced opacity (0.5), cursor not-allowed

**Task list (`#task-list`):**
- List-style: none, padding 0, margin 0
- Each `li.task-item`: flexbox row, align-items center, padding, border-bottom (subtle), gap between elements

**Task item internals:**
- `input[type="checkbox"]`: width/height ~18px, cursor pointer, margin-right
- `.task-title`: flex-grow 1, font-size readable
- `.task-title.completed`: text-decoration line-through, color muted (#999)
- `.delete-btn`: text or icon button, color red/muted, no background border, cursor pointer — OMIT in Phase 1 (it's defined so renderer.js can attach it later, but do NOT hide or disable it; just style it)

**Empty state (`#empty-state`, `.empty-state`):**
- Text-align center, color muted (#999), padding, font-style italic
- The `hidden` HTML attribute handles visibility — no CSS `display:none` needed for this

**Responsive:** The container max-width approach is sufficient for mobile — no media queries required.
  </action>
  <verify>After creating styles.css, open (or refresh) index.html. The page is visually styled — centered container, visible heading, styled input area. No unstyled page.</verify>
  <done>styles.css exists and covers all required selectors: body, .container, h1, .input-area, input, button, button:disabled, #task-list, li.task-item, input[type="checkbox"], .task-title, .task-title.completed, .delete-btn, .empty-state.</done>
